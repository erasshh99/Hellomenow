# 02 · Manifest analysis

The complete manifest of the original, grouped by what it means.

## 2.1 Permissions

| Permission | Present in original | Why it is there | In the rebuild |
|------------|---------------------|-----------------|----------------|
| `ACCESS_COARSE_LOCATION` | yes | transitive from `play-services-location`, unused by the app | removed |
| `ACCESS_FINE_LOCATION` | yes | idem | removed |
| `ACCESS_NETWORK_STATE` | yes | Play billing / in-app update | ✅ |
| `ACCESS_NOTIFICATION_POLICY` | yes | read and switch **Do Not Disturb** | ✅ |
| `ACCESS_WIFI_STATE` | yes | transitive | removed |
| `BLUETOOTH`, `BLUETOOTH_CONNECT` | yes | transitive | removed |
| `CAMERA` | no | — | removed (the rebuild does not need it) |
| `FOREGROUND_SERVICE` | yes | the keep-alive service | ✅ |
| `FOREGROUND_SERVICE_SPECIAL_USE` | yes | the keep-alive service, subtype `dynamic_island_overlay` | ✅ |
| `INTERNET` | yes | Play billing and in-app update | ✅ |
| `POST_NOTIFICATIONS` | yes | the keep-alive notification | ✅ |
| `RECEIVE_BOOT_COMPLETED` | yes | bring the island back after a restart | ✅ |
| `REQUEST_DELETE_PACKAGES` | yes | declared but the code uses `MediaStore.createDeleteRequest` | removed |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | yes | ask to be exempt from the battery saver | ✅ |
| `VIBRATE` | no | — | removed |
| `WRITE_EXTERNAL_STORAGE` | yes | legacy storage, unused on API 29+ | removed |
| `WRITE_SECURE_SETTINGS` | yes | declared, but never used by the app code | removed |
| `WRITE_SETTINGS` | yes | read/change the rotation lock | ✅ |
| `com.android.vending.BILLING` | yes | the Pro purchase | ✅ |
| `com.android.vending.CHECK_LICENSE` | yes | Play licence check | ✅ |
| `com.piyush.island.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | yes | auto-generated by AndroidX for context receivers | ✅ |
| `net.dinglisch.android.tasker.PERMISSION_RUN_TASKS` | yes | the optional Tasker integration | ✅ |

**Every permission the original declares is also granted by a user action in the app** except the
location, bluetooth and storage ones, which come from libraries the app never calls. The rebuild
therefore keeps the same set of permissions *that the app actually uses* and drops the six that
are dead weight. No permission was added by the rebuild.

## 2.3 The `<queries>` block

The original declares what it can see, which is what Android 11+ requires to look for other apps:

```xml
<queries>
    <intent><action android:name="android.intent.action.MAIN"/><category android:name="android.intent.category.LAUNCHER"/></intent>
    <intent><action android:name="android.intent.action.MAIN"/><category android:name="android.intent.category.HOME"/></intent>
    <intent><action android:name="android.appwidget.action.APPWIDGET_UPDATE"/></intent>
    <intent><action android:name="android.intent.action.EDIT"/><data android:mimeType="image/*"/></intent>
    <package android:name="net.dinglisch.android.taskerm"/>
    <package android:name="net.dinglisch.android.tasker"/>
    <intent><action android:name="com.android.vending.billing.InAppBillingService.BIND"/></intent>
</queries>
```

Translated: *installed apps* (for the app row and the alert filters), *home-screen widgets* (for
the widget gesture), *image editors* (for the screenshot card), *Tasker* (for the Tasker action)
and *Play Billing* (for the Pro purchase).

The rebuild uses the same block.

## 2.5 The service configuration

```xml
<service android:name=".overlay.IslandAccessibilityService"
         android:permission="android.permission.BIND_ACCESSIBILITY_SERVICE">
    <intent-filter><action android:name="android.accessibilityservice.AccessibilityService"/></intent-filter>
    <meta-data android:name="android.accessibilityservice" android:resource="@xml/accessibility_service"/>
</service>
```

The XML configuration of the original requests:

* `accessibilityEventTypes` — window state changes and window content changes
* `accessibilityFeedbackType` — `feedbackGeneric`
* `accessibilityFlags` — `flagDefault`, `flagRetrieveInteractiveWindows`, `flagReportViewIds`
* `canRetrieveWindowContent` — **false**: Shima does not read what is on the screen
* `notificationTimeout` — a short one, so the island notices changes quickly
* `canPerformGestures` — **true**, which is what makes the swipe and tap actions possible

The rebuild ships the same configuration.

## 2.6 The foreground-service declaration

```xml
<service android:name=".reliability.KeepAliveService"
         android:foregroundServiceType="specialUse">
    <property android:name="android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE"
              android:value="dynamic_island_overlay"/>
</service>
```

`specialUse` with the subtype `dynamic_island_overlay` is the correct declaration for an overlay
that has to stay alive; Android 14 and later require the subtype to be spelled out.
